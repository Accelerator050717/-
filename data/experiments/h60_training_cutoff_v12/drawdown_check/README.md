# 虚构连续亏损与恢复检查

全部价格、信号、标的、日期均为虚构，不是历史收益、2026行情或券商成交。使用现有 `profit_priority_strategy.simulate`，保留8股、15%保护、20%周期硬暂停、20日冷却及10日恢复，仅按主候选关闭软减仓。

八个虚构标的在两次相隔40个交易日的开盘分别下跌30%；中间满足原有趋势、冷却和计划调仓条件后恢复。跳空保护按原开盘滑点成交。

实际虚构输出：2次暂停、2次恢复、16笔跳空止损；全历史最大回撤 -42.521233%，最深周期回撤 -24.091103%。

现有 `DrawdownState.resume` 重置 episode_peak；但同次 `simulate` 输出的收盘回撤由完整权益路径的累计最大值（至少为初始权益1）计算，并不读取 episode_peak。`research_backtest.py` 也采用该累计高水位口径。因此用户30%预算须检查 `max_drawdown`，不能用重置后的周期回撤替代。

脚本同时用逐条累计的独立计算核对实际引擎结果，并将累计高水位/最深回撤经过JSON序列化后接续计算，证明保留统计状态时结果一致。这个检查不是新增的线上账户风险控制，也不能证明现有执行模块已经在长期断线、换模型或重启时保持账户高水位。重新调用 simulate 会从权益1开始；独立重启的归一化结果不能直接充当连续账户历史。

下一项独立风控设计应明确持久化账户高水位、现金流调整、重启/换模型的状态沿用及提前减仓/恢复规则，并另做收益代价实验；本轮单因素训练截止比较不混入该改动。跳空仍可能越过阈值。

运行：`.venv\Scripts\python.exe v12_drawdown_check.py`；测试：`.venv\Scripts\python.exe -m unittest discover -s tests -p test_v12_drawdown.py -v`。
