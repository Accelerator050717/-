## 字段与复权口径

| 字段 | 含义 |
| --- | --- |
| Date | 交易日期 |
| Open / High / Low / Close | 开盘价 / 日内最高价 / 日内最低价 / 收盘价，美元计价 |
| Adj Close | 进一步考虑股息和适用分配的调整收盘价 |
| Volume | 当日成交股数，ETF 为份数；不是成交金额 |
| Dividends | 当日记录的每股现金分配，0 表示该日未记录分配事件 |
| Stock Splits | 拆股事件比率；0 表示未记录拆股事件 |
| Capital Gains | 适用基金的每份资本利得分配；不是投资者的持仓盈亏 |

Yahoo 的 Close 已按拆股调整，不能称为“完全未复权”。`auto_adjust=False` 是保留 Close 与 Adj Close，不再由 yfinance 用 `Adj Close / Close` 统一变换 OHLC。Adj Close 是调整后的分析口径，不是当天可成交报价。后续分红等会影响更早日期的调整价，因此即使当天 Dividends 为 0，两种收盘价仍可能不同。

## 第 4 步：历史收益与候选特征（已运行）

运行：`.\.venv\Scripts\python.exe .\04_returns_and_features.py`。复用现有依赖和 CSV，不重新下载。

本步每行解释为当天收盘数据到齐后的观察时点，不假设能按当天收盘价成交，也不决定每天交易。`LOOKBACK = 5` 只是过去的观察窗口，不是未来预测周期或持仓期。使用 Adj Close 的区间比值，计算包含供应商分红调整的历史表现，不拿它当可成交报价。

核心逻辑在 `build_features()`：

```python
aapl_ret_1d = aapl_price / aapl_price.shift(1) - 1
aapl_ret_5d = aapl_price / aapl_price.shift(5) - 1
spy_ret_5d = spy_price / spy_price.shift(5) - 1
aapl_relative_5d = aapl_ret_5d - spy_ret_5d
```

## 第 12 步：让模型学习同日股票排序（已运行）

运行：`.\.venv\Scripts\python.exe .\12_train_ranker.py`。无需新依赖或重新下载。结果位于 `data/experiments/panel_ranker_v1/`；再次运行只显示已保存成绩。

问题：相同历史特征下，直接优化同日强弱顺序，是否有助于选股排序？继续使用原始5日未来超额收益作为排序依据，但将每一天30股从低到高转成0—4五档监督等级。代码取同日平均名次，计算 `floor((rank - 1) * 5 / 30)`；若真实收益并列则同档，不能按股票名称强行破并列。每档通常6股。22个历史X保持不变，新增等级不进入X。

```python
ranks = panel.groupby("Date")[TARGET].rank(method="average", ascending=True)
grades = np.floor((ranks - 1) * 5 / 30)
# 输入行必须按Date连续排列，group=[30,30,...]表示各日的股票数量。
ranker.fit(X_train, grades_train, group=stocks_per_date, ...)
```

LambdaRank 使用同一日期组内的股票相对顺序训练，强调将高等级股票排向前面；`label_gain=[0,1,2,3,4]` 明确采用线性等级权重。排序分数只有相对大小有意义，不能当成预测收益、概率、仓位或买卖指令。同日减去相同SPY收益不会改变股票名次，因此排第一也不保证绝对上涨或跑赢SPY。[LGBMRanker及日期分组接口](https://lightgbm.readthedocs.io/en/stable/pythonapi/lightgbm.LGBMRanker.html)

评价指标NDCG@5：按预测顺序查看前5个位置的真实等级，用随名次递减的权重加总，再除以当天理想排序的加权等级和。公式为 `sum(gain_i / log2(i+1), i=1..5) / 理想排序对应值`。0—1，越高越好；本数据恒分预测的并列平均参照为0.5，完美排序为1。预测分数并列时平均可能名次的贡献，避免股票名称/行顺序决定成绩。这不是准确率、胜率或收益率。[NDCG与并列处理](https://scikit-learn.org/stable/modules/generated/sklearn.metrics.ndcg_score.html)

为比较排序任务，收益回归树和排序树都使用相同的2023日均NDCG@5决定停止，关闭默认RMSE/NDCG指标；不能把这次回归树的13轮与上一轮按RMSE留下1轮混为同一实验。其他树容量参数沿用上一轮固定设置，没有网格搜索；两种学习目标的损失尺度不同，相同正则数值也不代表相同约束强度，这只是两种固定配置的一次比较。

## 第 13 步：年度重训与扩大容量（已运行）

运行：`.\.venv\Scripts\python.exe .\13_walkforward_training.py`。复用原30股、22特征、5日排序等级和依赖，输出 `data/experiments/walkforward_ranker_v1/`；重复运行只显示保存结果。

本轮检验两个问题：每年增加已发生的历史后重训，是否优于一直使用旧模型；把每棵树的叶子上限从31提高到127，是否改善以后的排序。每个叶子可以表示一种特征条件下的预测，更多叶子允许更细的划分，也更容易拟合偶然规律。这里扩大的是提升树容量，并非深度神经网络。[容量参数](https://lightgbm.readthedocs.io/en/stable/Parameters.html#num_leaves)

采用逐年扩展的训练窗口。每一折都从头训练，观察年Y的模型只学习至Y-2年，Y-1年决定训练轮数/候选，Y年用于开发比较；所有标签离场日必须早于各段终点。例如2025折：2015–2023训练、2024验证、2025开发。上一年评估过的数据可以在后续折中按真实先后顺序进入训练/验证，但每折当时的选择不能看到自己评估年的成绩。整个研究已看过这些历史，因此仍是回顾性开发，不是新独立测试。[按时间向前验证](https://scikit-learn.org/stable/modules/generated/sklearn.model_selection.TimeSeriesSplit.html)

固定6个评估年2020–2025 × 两档容量，共12次训练。每档最多3,000棵树，验证日均NDCG@5连续100轮不改善后保留最佳轮数；学习率0.03、叶子最少200样本、L2=10、种子42、4线程，其余沿用第12步。未搜索新的特征、预测周期、种子或更多参数。实际合计尝试1,873轮，保留673棵树，分别属于12个模型；不是一个673棵树的集成。各折训练样本从28,200增长到65,940，重复使用的历史不能累加为独立样本。
